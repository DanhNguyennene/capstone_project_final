\section{Frontend Implementation}
\label{sec:frontend}

This section describes the frontend architecture that provides the user interface for interacting with the Slurm Agent system. Rather than building a custom interface from scratch, this implementation integrates with Open WebUI, an established open-source AI chat platform, through a middleware architecture that bridges the platform to the custom agent backend.

\subsection{Architecture Overview}

The frontend implementation follows a three-tier architecture as illustrated in Figure~\ref{fig:frontend-architecture}:

\begin{enumerate}
    \item \textbf{Open WebUI}: The user-facing chat interface that provides a production-ready web application with conversation management, user authentication, and streaming display capabilities
    \item \textbf{FastAPI Middleware Router}: A custom router integrated into Open WebUI's backend that intercepts chat requests and forwards them to the agent service
    \item \textbf{Agent FastAPI Service}: A standalone service that implements the multi-agent system and exposes OpenAI-compatible API endpoints
\end{enumerate}

\subsection{Technology Stack}

The frontend leverages Open WebUI\footnote{\url{https://github.com/open-webui/open-webui}}, an extensible, self-hosted AI platform that provides comprehensive features for LLM interaction. Key technologies include:

\begin{itemize}
    \item \textbf{Open WebUI}: Production-ready chat interface with user management, conversation history, and multi-model support
    \item \textbf{SvelteKit} \cite{svelte2024}: The framework underlying Open WebUI, providing reactive UI components and efficient rendering
    \item \textbf{FastAPI} \cite{fastapi2024}: Both the middleware router (integrated into Open WebUI) and the standalone agent service
    \item \textbf{Docker \& Docker Compose}: Containerized deployment orchestrating Open WebUI, the agent service, and supporting infrastructure
    \item \textbf{aiohttp}: Asynchronous HTTP client for streaming communication between middleware and agent service
\end{itemize}

\subsection{Middleware Router Implementation}

The middleware router (\texttt{open\_agent.py}) is integrated as a custom router within Open WebUI's FastAPI backend. Its primary responsibilities include:

\subsubsection{Request Interception}

When users send messages through the Open WebUI chat interface, the \texttt{/chat/completions} endpoint intercepts these requests. The router extracts relevant metadata including the chat session identifier and user information:

\begin{verbatim}
chat_id = metadata.get("chat_id")  # Session continuity
user_id = user.id                   # User tracking
task = metadata.get("task", "chat") # Operation type
\end{verbatim}

\subsubsection{Request Forwarding}

The middleware forwards requests to the standalone agent service running on a configurable endpoint. The forwarding preserves the streaming nature of the response, enabling real-time display of agent output as it is generated:

\begin{verbatim}
AGENT_SERVICE_URL = "http://10.0.0.1:20000"
async with session.post(
    f"{AGENT_SERVICE_URL}/v1/chat/completions",
    data=payload,
    headers={"Accept": "text/event-stream"}
) as response:
    async for chunk in response.content:
        yield chunk
\end{verbatim}

\subsubsection{Session Propagation}

Critical to multi-turn conversation support, the middleware forwards the \texttt{chat\_id} from Open WebUI's metadata to the agent service. This enables the agent to maintain conversation history and context across multiple exchanges within the same chat session.

\subsection{Agent Service API}

The standalone agent service (\texttt{agent/main.py}) implements an OpenAI-compatible API that the middleware router consumes. Key endpoints include:

\begin{itemize}
    \item \textbf{\texttt{GET /v1/models}}: Returns the available model list, enabling Open WebUI to display ``slurm-agent'' as a selectable model
    \item \textbf{\texttt{POST /v1/chat/completions}}: The primary chat endpoint that processes user queries through the multi-agent system and streams responses
    \item \textbf{\texttt{GET /health}}: Health check endpoint for container orchestration
\end{itemize}

The service maintains session-based agent instances with automatic cleanup of expired sessions (default timeout: one hour). Each session preserves conversation history through the SQLite-backed session store.

\subsection{Streaming Response Flow}

The streaming implementation uses Server-Sent Events (SSE) throughout the entire pipeline:

\begin{enumerate}
    \item User submits query through Open WebUI chat interface
    \item Open WebUI sends request to middleware router
    \item Middleware establishes SSE connection to agent service
    \item Agent service streams response chunks as processing occurs
    \item Middleware forwards chunks to Open WebUI
    \item Open WebUI renders content incrementally in the chat interface
\end{enumerate}

Each SSE chunk follows the OpenAI chat completion format for compatibility:

\begin{verbatim}
data: {"id":"slurm-uuid","object":"chat.completion.chunk",
       "choices":[{"delta":{"content":"..."}}]}
\end{verbatim}

Special markers within the content field signal tool invocations (\texttt{[TOOL:name]}), agent handoffs (\texttt{[HANDOFF:agent]}), and embedded images (\texttt{[IMG]...[/IMG]}).

\subsection{Open WebUI Features Leveraged}

By building on Open WebUI rather than creating a custom interface, the implementation gains several production-ready capabilities:

\begin{itemize}
    \item \textbf{User Authentication}: Built-in user management with role-based access control
    \item \textbf{Conversation History}: Persistent chat sessions with search and organization
    \item \textbf{Markdown Rendering}: Rich text formatting including code blocks with syntax highlighting
    \item \textbf{Responsive Design}: Mobile-friendly interface that adapts to various screen sizes
    \item \textbf{Model Selection}: Users can switch between the Slurm Agent and other configured models
    \item \textbf{File Upload}: Infrastructure for future extensions involving job script uploads
\end{itemize}

\subsection{Deployment Configuration}

The complete system is deployed using Docker Compose, which orchestrates multiple services:

\begin{itemize}
    \item \textbf{open-webui}: The main frontend container with the integrated middleware router
    \item \textbf{slurm-agent}: The standalone agent service container
    \item \textbf{ollama} (optional): Local model inference for non-Slurm queries
\end{itemize}

Environment variables configure the connection between components, including the agent service URL and authentication settings. The containerized deployment ensures consistent behavior across development and production environments.
