\section{Module Specifications}
\label{sec:module-specifications}

This section provides a detailed breakdown of the MCP tool surface and the evaluation scoring methodology. Observer and Operator workflow details are described in Section~\ref{sec:architecture}.

\subsection{MCP Tool Layer}

\textbf{Dual Execution Mode}: The server supports \emph{real mode} (translates tool calls to Slurm CLI commands) and \emph{mock mode} (operates on mutable in-memory state with five predefined scenarios). Mock mode enables deterministic evaluation from known starting states.

\textbf{Parameter Validation}: Before execution, the MCP layer validates job IDs, node names, partition names, and scans batch scripts for dangerous patterns, providing a safety layer independent of LLM reasoning quality.

\subsection{Evaluation Pipeline}

Each benchmark test case $c \in \mathcal{C}$ specifies a tuple $(q_c, s_c^{\text{src}}, s_c^{\text{tgt}}, \mathcal{T}_c^*, h_c, \kappa_c)$ where $q_c$ is the natural-language request, $s_c^{\text{src}}$ and $s_c^{\text{tgt}}$ are the source and target cluster states, $\mathcal{T}_c^*$ is the expected tool set, $h_c \in \{0,1\}$ is the routing label (Observer-only vs.\ Observer$\rightarrow$Operator handoff), and $\kappa_c$ is the HITL requirement flag. The agent's response is scored across five weighted dimensions:

\begin{equation}
    \text{score}(c) = w_1 \cdot \text{TR}(c) + w_2 \cdot \text{R}(c) + w_3 \cdot \text{H}(c) + w_4 \cdot \text{S}(c)
    \label{eq:scoring}
\end{equation}

where the weights $(w_1, w_2, w_3, w_4) = (0.35,\, 0.25,\, 0.25,\, 0.15)$ sum to 1, and each component is defined as:

\begin{itemize}
    \item $\text{TR}(c) = |\hat{\mathcal{T}}_c \cap \mathcal{T}_c^*| \,/\, |\mathcal{T}_c^*|$ — \textbf{tool recall}: fraction of ground-truth tools invoked by the agent;
    \item $\text{R}(c) = \mathbf{1}[\hat{h}_c = h_c]$ — \textbf{routing match}: indicator that the agent's control-flow path matches the ground-truth label;
    \item $\text{H}(c) = \mathbf{1}[\hat{\kappa}_c = \kappa_c]$ — \textbf{HITL match}: indicator that the confirmation gate fired (or was correctly suppressed);
    \item $\text{S}(c) \in [0,1]$ — \textbf{state match}: fraction of expected job-state transitions correctly executed, verified against the mock cluster's post-run snapshot.
\end{itemize}
For the architecture ablation (Section~\ref{sec:ablation}), the monolithic baseline cannot satisfy $\text{R}(c)=1$ on any of the 237 handoff cases by construction. To enable a like-for-like quality comparison, routing is excluded and the remaining weights are re-normalised by $1/(1-0.25)$, yielding the ablation score:

\begin{equation}
    \text{score}_{\text{abl}}(c) = \frac{w_1}{0.75}\cdot\text{TR}(c) + \frac{w_3}{0.75}\cdot\text{H}(c) + \frac{w_4}{0.75}\cdot\text{S}(c)
    = \frac{7}{15}\cdot\text{TR}(c) + \frac{1}{3}\cdot\text{H}(c) + \frac{1}{5}\cdot\text{S}(c)
    \label{eq:scoring-abl}
\end{equation}

Both the dual-agent and monolithic baselines are scored with $\text{score}_{\text{abl}}$ for the ablation comparison, so the 6.1\,pp gap reflects only tool-recall and state-correctness differences.
The primary evaluation metric is the mean weighted score over the test set:

\begin{equation}
    \overline{\text{score}} = \frac{1}{|\mathcal{C}_{\text{test}}|} \sum_{c \in \mathcal{C}_{\text{test}}} \text{score}(c)
    \label{eq:mean-score}
\end{equation}

All reported results are averaged over $k=3$ independent trials with temperature $= 0$, making each trial fully deterministic; the reported figure is the mean across all trials. An optional LLM-as-judge provides supplementary quality scores on a 1--5 scale reported alongside the structural metrics.
