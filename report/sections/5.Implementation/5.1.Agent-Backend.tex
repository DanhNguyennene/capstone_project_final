\section{Agent Backend Implementation}
\label{sec:agent-backend}

This section documents the current backend implementation used in the updated project baseline (April 2026). The backend is responsible for: (i) maintaining session-aware multi-agent execution, (ii) exposing an OpenAI-compatible chat API for the frontend, and (iii) enforcing safety and confirmation policies for state-changing Slurm operations.

\subsection{Technology Stack}

The backend is implemented in Python and organized around asynchronous services:

\begin{itemize}
    \item \textbf{FastAPI + Uvicorn}: API layer for chat, health, and session endpoints
    \item \textbf{OpenAI Agents SDK}: multi-agent orchestration and tool-driven execution
    \item \textbf{aiohttp/httpx}: asynchronous streaming and external HTTP calls
    \item \textbf{SQLiteSession}: persistent per-session context and chat history
    \item \textbf{MCP over SSE}: tool discovery and execution against the Slurm MCP server
\end{itemize}

Model routing is configurable at runtime (local Ollama and optional remote providers), while the default deployment currently uses local Ollama.

\subsection{Runtime Agent Topology}

The operational agent topology is a main orchestrator with two specialized sub-agent tools:

\begin{itemize}
    \item \texttt{analyze\_cluster}: read-only cluster inspection and diagnostics
    \item \texttt{manage\_jobs}: state-changing operations (cancel, hold, release, submit, update)
\end{itemize}

In addition, the main agent directly exposes utility tools:
\texttt{generate\_chart}, \texttt{confirm\_action}, \texttt{cancel\_action}, and \texttt{check\_pending\_actions}.

This design keeps user-facing reasoning centralized while restricting high-risk execution to explicit action pathways.

\subsection{Safety and Confirmation Pipeline}

Dangerous operations are guarded through a queued-action workflow:

\begin{enumerate}
    \item A dangerous request is transformed into a pending action (not executed immediately).
    \item The user is shown the pending action and must explicitly confirm or cancel.
    \item Execution occurs only through \texttt{confirm\_action}; cancellation is handled by \texttt{cancel\_action}.
\end{enumerate}

This creates a two-step control path for destructive commands and reduces accidental cluster mutations.

\subsection{Session Management}

The API maps each chat ID to a persistent agent session, enabling stateful multi-turn behavior. Session state includes:

\begin{itemize}
    \item conversation memory,
    \item pending actions,
    \item chart artifact context,
    \item model/tool runtime configuration.
\end{itemize}

Session cleanup and explicit clear endpoints are provided to avoid stale context and to support evaluation reproducibility.

\subsection{Streaming Protocol (Current Format)}

Streaming responses use OpenAI-style SSE chunks with structured delta fields. Unlike earlier marker-based approaches, the current stream sends typed fields directly:

\begin{itemize}
    \item \texttt{status\_update}: tool progress and handoff status
    \item \texttt{tool\_output}: raw tool output fragments
    \item \texttt{reasoning\_content} / \texttt{reasoning}: model thinking tokens
    \item \texttt{content}: final user-visible answer tokens
    \item \texttt{chart\_artifact}: Mermaid payloads for rendering
    \item \texttt{todo\_update}: task-plan updates
    \item \texttt{pending\_actions}: queued actions awaiting user confirmation
\end{itemize}

This explicit schema simplifies downstream parsing in both chat UI and evaluation pipelines.

\subsection{Chart Artifact Isolation}

Chart rendering uses Mermaid artifacts generated as tool outputs and streamed separately from natural-language reasoning. To prevent context pollution, chart artifacts are filtered out of future LLM context windows via session wrappers. This preserves token budget and avoids recursive visual-text contamination.

\subsection{Evaluation-Oriented Backend Hooks}

The backend now exposes behavior that supports architecture-level evaluation:

\begin{itemize}
    \item deterministic session IDs for replayable traces,
    \item detailed status/tool streaming for trace extraction,
    \item compatibility with state-reset workflows in mock MCP mode,
    \item explicit HITL event visibility for safety scoring.
\end{itemize}

These hooks are consumed by the Scenario-Grid evaluation stack described in Chapter~\ref{sec:testing-approach}.
