\section{Frontend Implementation}
\label{sec:frontend}

This section describes the current frontend architecture for interacting with the Slurm Agent system. The active implementation is a custom React + Vite web application with two integrated modes: a chat interface and an evaluation dashboard. An Open WebUI bridge remains available as an optional compatibility deployment path.

\subsection{Architecture Overview}

The frontend stack can be used in two modes:

\begin{enumerate}
    \item \textbf{Primary mode (used in this report)}: React + Vite frontend (chat + evaluation views) communicating directly with the agent API and evaluation API.
    \item \textbf{Compatibility mode}: Open WebUI + middleware router forwarding to the same agent API.
\end{enumerate}

\subsection{Technology Stack}

The active frontend uses the following stack:

\begin{itemize}
    \item \textbf{React 18 + Vite}: client rendering and build tooling
    \item \textbf{FastAPI} \cite{fastapi2024}: agent backend and evaluation backend APIs
    \item \textbf{SSE over Fetch Streams}: incremental rendering of reasoning, status, and answer tokens
    \item \textbf{Mermaid}: inline chart rendering in chat/evaluation artifacts
    \item \textbf{LocalStorage-based session state}: frontend conversation persistence
\end{itemize}

\subsection{Primary Frontend Structure (React Application)}

The primary application is composed of modular React components:

\begin{itemize}
    \item \textbf{App shell}: top-level layout and view switching (Chat/Eval)
    \item \textbf{Sidebar}: sessions, server settings, and mode toggle
    \item \textbf{Messages/Input components}: conversational interaction and HITL action buttons
    \item \textbf{Eval view}: dataset loading, run controls, live progress, per-test trace inspection
\end{itemize}

The integrated evaluation view allows end-to-end testing without leaving the primary UI. It displays per-test status, model traces, and aggregate metrics in real time.

\subsection{Streaming Response Flow}

The frontend consumes OpenAI-compatible SSE chunks from the backend. Key delta fields include:

\begin{itemize}
    \item \texttt{status\_update}
    \item \texttt{tool\_output}
    \item \texttt{reasoning\_content}
    \item \texttt{content}
    \item \texttt{chart\_artifact}
    \item \texttt{todo\_update}
    \item \texttt{pending\_actions}
\end{itemize}

This structured stream enables independent rendering of tool traces, model thinking, final answer content, and user confirmation controls.

\subsection{Evaluation UI Integration}

The evaluation interface is now a first-class frontend mode. It provides:

\begin{itemize}
    \item dataset load/upload and filtering,
    \item run-all and run-single controls,
    \item real-time test progression with pass/fail states,
    \item per-test drill-down for tools, routing, HITL, response, thinking, and judge output,
    \item aggregate metrics display.
\end{itemize}

This integration shortens the iteration loop between feature development and behavioral evaluation.

\subsection{Optional Open WebUI Integration Path}

Open WebUI integration remains available for environments requiring Open WebUI ecosystem features (organizational deployment, existing plugin stack). In this mode, a middleware router forwards chat requests to the same agent backend. This path is considered optional in the current implementation baseline.

\subsection{Agent Service API}

The frontend communicates with OpenAI-compatible endpoints exposed by \texttt{agent/main.py}. Key endpoints include:

\begin{itemize}
    \item \textbf{\texttt{GET /v1/models}}: model list exposure
    \item \textbf{\texttt{POST /v1/chat/completions}}: The primary chat endpoint that processes user queries through the multi-agent system and streams responses
    \item \textbf{\texttt{GET /health}}: Health check endpoint for container orchestration
\end{itemize}

The dedicated evaluation backend (\texttt{evaluation/eval\_server.py}) exposes additional endpoints for dataset loading, test execution, stopping, and persistent result snapshots.

\subsection{Current User-Facing Capabilities}

The frontend currently supports:

\begin{itemize}
    \item live chat with streaming responses,
    \item HITL confirmation/cancellation controls,
    \item inline markdown and Mermaid rendering,
    \item multi-session navigation,
    \item integrated evaluation workflow in a dedicated tab.
\end{itemize}

\subsection{Deployment Configuration}

The project includes script-based startup for local development:

\begin{itemize}
    \item \textbf{start.sh}: launches MCP server, agent API, and built frontend preview
    \item \textbf{start\_eval\_server.sh}: launches standalone evaluation backend
    \item \textbf{MCP scenario switching}: allows deterministic evaluation in healthy/failed/pending/mixed/debug\_needed states
\end{itemize}

Containerized and Open WebUI-based deployments remain possible, but are not the only deployment model.
