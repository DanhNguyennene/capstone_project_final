\section{Limitations}
\label{sec:limitations}

The current Slurm Agent demonstrates promising behavior, but several limitations remain before production-grade deployment.

\subsection{Evaluation Realism Limitations}

\textbf{Mock-state dominance.} The benchmark primarily uses deterministic mock scenarios. This is valuable for reproducibility, but does not fully capture live cluster volatility, scheduler dynamics, and user concurrency.

\textbf{Single benchmark snapshot emphasis.} Current reporting centers on the latest full snapshot. Broader confidence intervals across repeated full runs are not yet fully reported in the thesis body.

\textbf{Limited human-subject evaluation.} Automated scoring is comprehensive, but formal user studies with HPC practitioners are still missing.

\subsection{Behavioral Reliability Limitations}

The latest 367-case results expose reliability gaps in specific categories:

\begin{itemize}
    \item \textbf{multi\_step}: 0\% pass in the latest snapshot,
    \item \textbf{safety}: 53\% pass,
    \item \textbf{submission}: 51\% pass.
\end{itemize}

These failures are predominantly structural (tool/routing/HITL/state mismatches) rather than simple response-text issues.

\subsection{Operational Scope Limitations}

\textbf{Read-heavy maturity.} Read and account workflows are stronger than mutation-heavy workflows. Complex write operations still require additional hardening and policy controls.

\textbf{Narrow deployment validation.} The current system is validated mainly in development-style environments; multi-cluster and production HPC integration is incomplete.

\subsection{Security and Governance Limitations}

\textbf{Authentication and authorization are incomplete.} Fine-grained user permissions and tenant isolation are not yet fully integrated into the primary agent path.

\textbf{Auditability needs extension.} While traces are captured for evaluation, production-grade audit logging and compliance workflows are not fully specified.

\subsection{Performance and Scalability Limitations}

\textbf{Latency variability persists.} Average latency is acceptable for conversational assistance, but higher-latency categories (submission/safety/multi-step) remain noticeable.

\textbf{Concurrent-load behavior is under-tested.} Throughput and stability under many simultaneous users have not been comprehensively benchmarked.

\subsection{Model and Scoring Limitations}

\textbf{Model sensitivity.} Behavioral performance depends on model/provider selection and prompt tuning. Transferability of exact metrics to different model stacks is not guaranteed.

\textbf{Judge dependence.} Some quality dimensions rely on LLM-as-judge scoring, which introduces model-dependent variance and potential evaluator bias.

\subsection{TODO for Limitation Mitigation}

    \item Execute controlled live-cluster pilot tests with strict permission boundaries.
    \item Add production-oriented authz/audit requirements and verification checklist.
\end{itemize}
